## 3. Decisions taken inside WP-2A (not in the spec text; review them)

1. **Part names.** Template segments are named `template`; the inputs are `project-instructions`, `agent-contract`, `agent-role`, `repository-context`, `mode`, `task`, `specification`, `review`; the constant user prompts are `user-prompt`. The `mode` value is labelled `instruction` (the spec did not classify it; it is a harness-controlled enumerated value). `parts` in a builder result is the system breakdown followed by the prompt part.
2. **`-RepositoryContext`.** Present (even as an empty string) adds the context section; absent adds none. The legacy script rejects blank context before building the prompt, so that case never reaches the builder; the caller keeps that check.
3. **No golden is LF-only**, so the spec's guard "a golden meant to be LF-only contains no carriage return" became a literal count of CRLF, LF-only and lone CR for the 8 fixture inputs plus the `.gitattributes` content check, which detect the same loss of bytes.
4. **Fixtures are files** (with `-text`), and the pass-through test builds its CRLF, LF and mixed inputs in memory, as FR-203 now says.
5. **The capture and generator scripts are not committed** (NFR-206 lists the files that may be created). The method is in section 2.1; the template text is in the library and the goldens are reproducible by recapturing from the unmodified scripts.
6. **Library file encoding.** `agent-exec.ps1` is ASCII only (checked by the generator), so it does not depend on a BOM; its own line endings do not matter (tested).

## 5. NOT VERIFIED

- Anything live: no Ollama call was made, and a real request body was not captured.
- Behavior on a checkout whose scripts are LF: the strict equality of 2.1 is a property of this CRLF checkout; the normalized comparison is what the suite asserts and is independent of it.
- That the future WP-2D scripts send exactly these prompts (AC-201 script part).
- The goldens embed the fixture inputs' bytes; a different Git client configuration that ignores `.gitattributes` would alter them, but the fixture-bytes test would then fail.
