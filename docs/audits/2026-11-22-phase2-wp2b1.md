## 7. Decisions made that the spec does not state (for review)

1. **Commit structure.** The registry change and the suite share one commit (see section 1).
2. **Error tokens** are the spec's field paths: `registry_invalid: ollama.maxAttempts`, `ollama.retryBackoffSec`, `ollama.warmup`, `defaults.charsPerToken`, `defaults.budgetMode`. Phase 1 is inconsistent: `ollama.healthTimeoutSec` uses the full path, but `defaults.timeoutSec` and `defaults.safetyMarginRatio` use only the last key (`timeoutSec`, `safetyMarginRatio`). I followed the spec table and the `ollama.*` precedent.
3. **`budgetMode` is case-sensitive** (`"WARN"` and `"Enforce"` are rejected), matching how `think` is validated.
4. **JSON `null`** for any of the five fields counts as absent and takes the default (`Get-ConfigValue` behavior shared with every Phase 1 field).
5. **`2.0` and `10.0`:** `ConvertFrom-Json` returns a double for `2.0`, so `"maxAttempts": 2.0` is rejected as non-integer (existing `Test-HarnessInteger`). `charsPerToken` 10.0 is accepted.
6. **Single-element arrays** (`"maxAttempts": [2]`) are accepted as `2`, because `Get-ConfigValue` unrolls them in the pipeline. This predates this package and affects every Phase 1 field too. Not changed (smallest change); I removed my test case for it rather than assert it. Worth a note for a later hardening pass.
7. **Skipped budget record:** `status` `skipped`, every number `$null`, `sections` empty. The spec says "nothing is reported" and FR-216 wants empty `context_window` and `est_prompt_tokens`; `null` serves both.
8. **Not-exceeded `over`** is `0` (the spec says "when positive"). All numbers are `[long]`.
9. **`-Parts`** accepts parts (`Name`, `Kind`, `Text`) and breakdown entries (`name`, `kind`, `chars`) as `New-AgentPrompt` and the builders return them. Section tokens are `ceil(chars / charsPerToken)` per part, so the sections' token sum can exceed the total `estTokens` by up to one per part; only the characters sum exactly to the prompt length.
10. **`Test-AgentContextBudget` throws `invalid_arguments:`** for an `-Execution` without `contextWindow`/`reservedOutputTokens` members or a `-Registry` without `defaults.safetyMarginRatio`/`charsPerToken` (programmer errors, FR-210), and does not fall back to hardcoded constants.
11. **`Get-AgentRetryDelaySec`** has no `-CapSec` parameter (the cap is fixed at 60, per the brief), accepts any non-negative base (a base above 60 is capped, though the registry never allows it) and requires `-Attempt >= 1`.
12. **Test-name scope collision found while writing the suite:** a `foreach ($name ...)` around a `Test-Case` call shadows the helper's `$Name` parameter because PowerShell variables are case-insensitive. Fixed in the new suite; existing suites were not inspected for it.
