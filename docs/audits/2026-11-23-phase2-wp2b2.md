## 7. Decisions made that the spec does not state (for review)

1. **Shape of `Get-AgentErrorCategory`.** Two parameter sets: `-Failure -HttpStatus` (classify) and `-Category <name>` (the fixed record of a named category, used for the categories the engine assigns itself: `context_budget_exceeded`, `thinking_budget_exhausted`, `empty_response`, `format_invalid`, `model_not_installed`). Both return `{ category, retryable, hint, detail }`; `detail` is `''` by name. FR-201 allows no extra function, so every hint has one home here. An unknown name throws `invalid_arguments:`.
2. **The Ollama JSON body only builds `detail`.** The brief says classify "by exception type, HTTP status and Ollama error JSON body"; FR-211 says the category uses only `httpStatus`, `exceptionType` and `webStatus`, and that `detail` never decides anything. I followed the spec: the body is read only for `detail` (mutation E16, "category decided by the body", is killed).
3. **Exact matching.** `webStatus` and type names are compared case-sensitively and by full type name (a subclass is `transport_other`); the enum names come from `ToString()`, so exact case holds.
4. **HTTP status coercion.** A status given as text is parsed as an integer; blank means none; an unparsable one is an "other HTTP status" (`transport_other`, still beating a webStatus).
5. **`detail` fallback** is `<exceptionType> <webStatus>` (space, missing parts omitted) or `unknown`; a JSON `error` that is not a non-empty string falls back.
6. **Hint wording** is mine (English, one line, ASCII). Only the property "mentions restarting Ollama" for `http_5xx` and `transport_reset` comes from the spec's example.
7. **Writer parameters.** `-Profile -ModelSource -Transport -ModelCalled -Attempts -ErrorCategory -HttpStatus -DoneReason -ThinkingChars -ThinkSent -TimeoutSec -ContextWindow -PromptChars -EstPromptTokens -Warnings`; the caller supplies the numbers (the writer computes none). `-ErrorMessage` stays and is the detail. Defaults: `model_called` true (the legacy call logged after a request), `transport` `blocking`, everything else empty. `think_sent` defaults to empty, not `omitted`, because the writer cannot know. `done_reason` falls back to `Response.done_reason`.
8. **`error` column.** The 500 limit applies to the whole `<category>: <detail>` string; each CR and each LF becomes one space (CRLF gives two); a cut that would split a surrogate pair stops at 499; a category with no detail is just the category. The legacy no-category form is sanitised and cut too.
9. **Value types.** JSONL: numbers are numbers, `model_called` a JSON boolean, unmeasured values `""` (as the spec says), legacy `Response` columns stay `null`. CSV: booleans are lower case `true`/`false` (a copy of the record is converted, because `ConvertTo-Csv` would write `True`).
10. **CSV details.** The header compared is the quoted `ConvertTo-Csv` form of the record being written (spec review, point 4). A new file is created with `Set-Content -Encoding UTF8` (BOM on PowerShell 5.1, as the legacy `Export-Csv` did). When no CSV can take the row, the writer raises one `Write-Warning` with harness-owned text (the spec says only "skip the CSV row"; a silent loss seemed worse). An empty `model-calls.csv` is "another header": the v2 file is used and the empty file stays empty.
11. **`-Profile` is a writer parameter name.** It shadows the automatic `$PROFILE` inside the function (the lesson of WP-2B1); the function does not use `$PROFILE`.
12. **Fake transport.** Steps (record, exception, script block), `-RepeatLast`, and `failure.message` as a display-only member (OQ-214). Calls record the decoded and parsed body. `New-FakeGenerateResponse` omits `thinking` unless given.
13. **Suites are in-process.** No child process and no sandbox are needed: the classifier is pure and the writer only writes under one TEMP folder, removed at the end. A guard asserts every case root is under that folder.
14. **Held back by topic, from `feat`.** Two wip branches rather than one, so each can be accepted or rejected with its own edits.
