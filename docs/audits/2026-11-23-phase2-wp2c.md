## 5. What this package does not prove (NOT VERIFIED)

- Everything live: no Ollama, no network, no real sleeping.
- `Invoke-OllamaHttp` against a **real** `Invoke-RestMethod` and a real `WebException`: the `ErrorDetails` path is exercised only with an `ErrorRecord` the test builds. That PowerShell 5.1 stores the response body in `ErrorDetails` for web cmdlets is the A-201 assumption; the stream fallback covers the other case.
- `[string]$errorRecord.ErrorDetails` giving the body relies on `ErrorDetails.ToString()` returning its message; verified with a constructed `ErrorDetails`, not with one produced by the cmdlet.
- The real success status: `Invoke-RestMethod` does not expose it; the transport records 200 (decision 6).
- Real language independence of .NET messages (they are never read; es-ES, en-US, tr-TR cultures tested with fakes only).
- Child-process behavior (fake host, guard 2, `-ErrorAction` rejection by the Phase 1 hosts' own parameter lists): WP-2D. The in-process runtime fake accepts `-ErrorAction`; a static check covers it here.
- Concurrency of two processes writing telemetry; warm-up value (ASSUMPTION A-203); that `think` is accepted by real models.
- The mutation harness and raw results are in `%TEMP%`, not committed.

## 7. Decisions made that the spec does not state

1. **`meta.callId` and the telemetry `call_id` differ.** The writer generates its own GUID and has no parameter to receive one; `telemetry.ps1` is outside this package. If WP-2D wants them equal, the writer needs an optional `-CallId`.
2. **No `failure.message`.** OQ-214 allowed a display-only member; the AC-207 static scan forbids any `Message` lookup in the transport, and the fake (`New-FakeFailureRecord`) offers `message` only as optional. The real record has `exceptionType, webStatus, body` only. WP-2D's error block therefore prints `Status`, the body, `Category`, `Hint`, and no message (NFR-205 already lists this as intentional). The body is read with `[string]$errorRecord.ErrorDetails` (its `ToString()` is the body text) so that the scan, which would flag `.ErrorDetails.Message`, needs no edit.
3. **A thrown WebException from an injected transport is `transport_other`** (the spec says `webStatus` `$null` for a throwing transport); only the default transport reads `Status`.
4. **`thinkingChars` counts the inner text of each removed `<think>` block** (not the tags or trailing whitespace); the spec says "the length of any removed blocks".
5. **`thinkSent` and `think_sent` are empty when no request was built** (budget refusal, model not installed); the spec lists three values.
6. **Success `httpStatus` is 200** (assumed; the cmdlet returns only for 2xx and Ollama answers 200).
7. **`model_called` is true once any request (warm-up included) was sent**, false for refusals and `Test-OllamaModel` failures. `meta.attempts` is the number of attempts of the phase that ended the call (warm-up attempts when the warm-up failed); 0 for a budget refusal, written to telemetry as empty.
8. **`OnRetry` receives the number of the attempt about to be made** (2 after the first failure), matching the console line of M-6; a wait of 0 s skips the `-Sleep` call but still calls `OnRetry`; `OnRetry` exceptions are swallowed.
9. **`-ResponseCheck`**: only the first output counts; null, empty or blank is acceptable; an exception inside it becomes `format_invalid` with detail `response_check_error` so the one-record rule holds; the kept text is the interpreted (stripped, trimmed) text.
10. **`Test-OllamaModel`** returns `{ available, category, models, detail, hint, httpStatus }` (the spec names the first three); `category` is `$null` when available; only a successful `/api/tags` is cached; with a failure it makes no retry.
11. **Warm-up key** is URL plus model, case-insensitive; a failed warm-up is not remembered; `meta.warmup` is `$null` (disabled) or `{ state: sent|cached|failed, attempts, category }`.
12. **Resolution warnings** (`unregistered_model_override`) are not copied into `meta.warnings` or the telemetry `warnings` column (the spec's warning codes are the engine's own).
13. **Body bytes** keep their type through the block that builds them (a unary comma); the first draft returned `object[]`, which the fake body check caught.
14. **The scan edit in `test-agent-prompts.ps1`** is 11 lines, not 1: the forward-compatible form needs the owner-block check; it mirrors `test-agent-errors.ps1`.

## 8. For the independent Opus reviewer to attack

1. **`Invoke-OllamaHttp` on real PowerShell 5.1.** Does `$_.ErrorDetails` hold the body for a real 4xx/5xx? Is `[string]$errorRecord.ErrorDetails` really `Message`? Does `$exception.Response.StatusCode` exist for a real `HttpWebResponse` and is the stream still readable after `ErrorDetails` was filled (it is not read then)? What if `$exception` is not a `WebException` but wraps one?
2. **The splat.** One call with `@arguments`: any hidden parameter? `-Body` as `byte[]` with `-ContentType` charset: does the real cmdlet re-encode it?
3. **Retry semantics.** Off-by-one on `tries < maxAttempts`; `OnRetry` argument meaning; `Get-AgentRetryDelaySec -Attempt $tries`; worst-case time (RK-203); a retry after a *warm-up* success but generation failure re-sends only the generation (intended).
4. **One record per call.** Is there any path that returns before the writer (other than programmer errors)? Exceptions thrown by `Test-AgentContextBudget` or the writer's binding (blank agent/model) before the record. `Test-OllamaModel` plus `Invoke-AgentModel` together are two records for a call that fails in the second; the first writes only when unavailable, so one per call, but the scripts must not call both with `-TelemetryRoot` and ignore a "not available" result.
5. **`think`**: only a real boolean and a non-empty profile name; `Execution.think` absent; a `$false` read through `Get-ConfigValue` (the WP-2B2 unrolling lesson) all the way to the body; `think` in the warm-up (never).
6. **Budget**: `warn` proceeds, never truncates; `enforce` check runs before the body is built and before any warm-up; `-Parts` shape (parts vs breakdown) accepted; `skipped` for v1.
7. **Interpretation**: regex unchanged from the legacy code; empty-after-strip with `length`; `thinkingChars` choice (decision 4); `done_reason` null; a `response` that is not a string; `possible_prompt_truncation` uses `>=` with `C - R`.
8. **Variable shadowing** (case-insensitive names) in the long function: `$Parts`/`$parts`, `$Prompt`/`$prompt`, `$System`, `$Transport` versus the local script blocks (`$send`, `$sendWithRetry`), `$record`, `$answer`; script-block closures reading outer variables dynamically (`$attempts`, `$maxAttempts`, `$Sleep`, `$OnRetry`).
9. **Static scans as proof.** The `.Message`/`Message` scan is syntactic: is there another way to read the message (`$_.ToString()`, `$_ | Out-String`, `-ErrorVariable`)? `ErrorDetails` `ToString()` is the deliberate route (decision 2).
10. **Telemetry values**: `http_status` blank vs 200; `think_sent` blank on refusals; `attempts` blank for refusals; `error` column built as `<category>: <detail>` with the detail from Ollama's JSON `error` (up to 500 characters; may contain model text).
11. **Suite quality**: fixtures that agree with the code by construction (the fake `Invoke-RestMethod` is a simple function: it accepts `-ErrorAction`); equivalent mutant W5; mutants I did not write (for example `Get-AgentErrorCategory` rows other than R1, the CSV rule, the registry defaults); the NFR-201 measurement uses a fake that returns instantly and a warm temp folder.

Mutation-checked in a TEMP copy after the batch: a second `Invoke-RestMethod` call inside `Invoke-OllamaHttp` -> suite fails (more than one call); a call inside `Reset-AgentExecState` -> fails (`outside Invoke-OllamaHttp`); the alias `irm` -> fails (`forbidden command: irm`).
