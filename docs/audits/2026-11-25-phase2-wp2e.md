## 7. Anomalies and limits of this run

| ID | What | Effect |

## 9. PROPOSED `.ai/config.json` changes (not applied)

**No change to the shipped configuration is proposed on this evidence.** The proposal below is a decision rule to apply when the measurements exist, so that the numbers decide and not this report.

| Setting | Proposal now | Reason and rule for later |
|---|---|---|
| `defaults.charsPerToken` | Keep 3.5 | One measured ratio (5.43, English instruction text) and one historical indication (about 5.3). Both say the estimate is too high for this kind of prompt, which is the safe direction. Code, Catalan and Spanish text normally give fewer characters per token and were not measured, so raising the value on this data could turn the budget into an under-estimate. Rule: set the value to the smallest ratio measured over all content types the harness sends, rounded down to 0.1, and keep a margin for the content that was not measured. |
| `defaults.budgetMode` | Keep `warn` (no key) | The reviewer warning is probably a false positive (section 8, 2b), so `enforce` would block a call that works today (RK-201). Decide `enforce` only after the real reviewer and reviser counts are measured. |

## 10. Recommendations

**To resume WP-2E (owner action first):**

1. The owner restarts the Ollama server (the engine's own hint says so, and the 2026-11-19 case was cleared this way). This run was not allowed to do it. Then repeat the preflight and record the result.
2. Before the first 35b call, check that no other model is resident (`ollama ps`) and record the free VRAM; allow a smaller first step: one reviewer call on the 712-byte fixture, alone, to see that `qwen3.6:35b` loads at all. If it fails again, stop and report; no measurement of the 35b model is possible until the fault is cleared.
3. Reuse the scratch runner in `%TEMP%\wp2e` if it is still there (inputs of 2, 8, 16 and 60 KB, the Spanish and Catalan texts, the code and prose contexts), after fixing A1. Planned use of the budget: about 33 of the 45 calls, so the fault costs nothing of the plan. Three calls are already spent.
4. For the calibration, vary the prefix between calls or accept only the first call after a different prompt, and flag any `prompt_eval_count` far below the expected value as a cache effect (A3).

**For Phase 3:**

1. A failed model load repeated after 5 s fails again (here, twice 55 s). A `http_5xx` whose body says `Load failed` or names a CUDA error is a runtime fault, not a transient one; consider a different category, or no retry for it, so that the user does not wait for the second 55 s and sees the restart hint at once. This rests on one observation plus the earlier fault logs.
