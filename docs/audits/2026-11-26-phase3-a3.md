Date: 2026-11-26. Branch `claude/phase3-a3-suite-split-938c3e`. Implements FR-315, exit check AC-323.

## Executive summary

**What changed.** `scripts/test-engine-callsites.ps1` (1956 lines, 152 cases) is deleted. Three suites replace it, over one helper:

- `scripts/test-engine-callsites-run-agent.ps1` (58 PASS), `-review-spec.ps1` (52), `-revise-spec.ps1` (60).
- `tests/lib/engine-fake-host.ps1`: fake host, `New-TempHarness`, `Invoke-Case`, the four guards, assertion helpers, shared configs and data, summary. Not named `test-*`; `test-all.ps1` does not run it.
- `tests/lib/compare-engine-case-names.ps1`: the AC-323 check (not a suite; run by hand or by the QA session).
- `tests/fixtures/engine-callsites-cases.txt`: the 152 names printed by the old suite, run on the unchanged tree before any edit.
- No case body, assertion or expected value was edited. Code was moved by line ranges from the old file; `test-all.ps1` is unchanged (it discovers `scripts\test-*.ps1`, no hand list).

**AC-323 evidence.**

| | PASS lines |
|---|---|
| Old suite (baseline run, unchanged tree) | 152 = 143 cases + 9 guard proofs |
| New suites | 58 + 52 + 60 = 170 = 143 cases + 3 x 9 guard proofs |

- Each suite runs the four guards (FR-315), so each prints the 9 guard-proof lines (7 for guard 1, one accept line, one for guard 4). The old suite printed them once. That is the only addition: +18 PASS lines (152 + 18 = 170). I read this as what AC-323 allows ("counts add up"); see doubts.

**test-all (one final run, committed tree).** Discovered 21 (was 19 at `phase2-calibrated`: minus 1 old suite, plus 3), executed 20, PASS 20, PASS WITH SKIPS 0, FAIL 0, skipped 1 (`test-spec-integration.ps1`, needs Ollama). `STATUS: PASS WITH SKIPS`. Tripwire clean. The three new suites took 57.8 s, 50.5 s and 57.0 s (limit 300 s).

**Mutation proof (AC-323 key rule: a renamed case is caught).** Temporary edit of `test-engine-callsites-revise-spec.ps1`: "in case" became "in CASE" in one case name. The suite still passed (exit 0, 60 PASS). The check on the three logs then failed (exit 1) with `MISSING ... differs only in case is installed` and `UNKNOWN ... differs only in CASE is installed`. The file was restored from a copy and the SHA-256 matched before and after (`79829813c1437a4ac628aec7b9b4470f071fc994640bf5a33a948e9109ea79c7`). The same check on the unmutated logs passes.
- The proof found a real defect in my first version of the check: a PowerShell hashtable ignores case, so the case-only rename was reported as present. The tables are now ordinal and I repeated the proof after the fix.

**Stale comment.** The guard-4 comment ("the wrappers are relocated and delegate to the engine") now says the wrappers no longer exist (FR-314) and that the engine transport is the only caller of the cmdlet. Nothing else was reworded.

**Deviations and decisions to confirm.**
1. Guard-proof lines are counted once per suite (see above). The check treats names starting `guard ` as that class.
2. The nine guard names and the 143 cases are in one fixture file; the fixture is committed (AC-323 names it) as well as the temp log used for the proof.
3. The case "AC-216 review-spec and revise-spec reject a -Mode outside the ValidateSet" loops over both scripts in one case. As FR-315 says, it goes with its first script: the revise-spec bad-`-Mode` call is no longer exercised. The same cut applies to no other case.
4. "AC-322 the wrappers are gone" is not tied to a script; I put it in the run-agent suite.
5. Shared data that the old main body defined in the middle (`$inputsText`, `$matrixConfig`, `$bigTask`, the three `$tiny*` configs, `$taskPath`, `$specText` and the like) moved into `Initialize-EngineSuite` in the helper, set with `$script:`, so the suites do not copy it. Same values, same text.
6. The affected-files list names no place for the compare script; I used `tests/lib/`.

**Not verified / doubts.**

- The logs for the AC-323 check came from the same suite code before the comment edit and the CRLF normalization of two files; `test-all` ran after both and passed, but the check was not rerun on that final tree.
