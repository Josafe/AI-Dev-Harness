# Phase 3, package A4: engine signals

Date: 2026-11-26. Branch `claude/phase3-a4-engine-signals-4b4193`. Implements FR-316, FR-317 and the library half of FR-318 (`Test-OllamaModelLoad`). Exit checks AC-331, AC-332 and the library half of AC-333.

## Executive summary

**What changed (engine, `scripts/lib/agent-exec.ps1`).**
- **FR-316.** `Invoke-AgentModel` adds `prompt_truncation_detected` when `promptChars > 7 * n`, with `n` the response's `prompt_eval_count` when it is a real number (int, long, decimal, double) above 0. The constant lives in the engine (`$truncationCharsPerToken = 7`). Absent, 0, negative, string, NaN, boolean, array or object adds nothing and never throws. `possible_prompt_truncation` keeps its rule. The call outcome is unchanged (RN-3). The warning is added after the old one, so the order is old, new.
- **Corroborating signal `n == floor(num_ctx/2) + 2`: NOT implemented.** The spec calls it a RECOMMENDATION (FR-316 Probe), not a requirement.
- **Warning lines.** `run-agent.ps1`, `review-spec.ps1`, `revise-spec.ps1` print, after the `budget_exceeded` line, one yellow `Warning: prompt_truncation_detected (...)` and one `Warning: possible_prompt_truncation (weak signal: ...)` per warning present (RN-2).
- **FR-317.** `Get-AgentErrorCategory`: HTTP 500 to 599 whose Ollama JSON `error` string contains `Load failed`, `CUDA error` or `llama-server process has terminated` (ordinal, case-sensitive) is `model_load_failed`, never retried (one attempt, no wait, no `OnRetry`), also for a warm-up. 4xx, non-JSON body, other 5xx unchanged. The text search is in a new pure function `Test-OllamaLoadFailureText`, so the classifier itself has no text search and the Phase 2 NFR-202 static scan is unchanged. The hint is new text (contains "Restarting the Ollama server" and "rebooting the machine"); the `http_5xx` and `transport_reset` hints are byte-identical (RN-16, pinned by a new case). Phase 2 `specs/harness-phase-2-shared-engine.md` NFR-202 got the one-line note.
- **FR-318 library.** `Test-OllamaModelLoad -Execution -Registry [-Transport]` returns `{ loaded, category, hint, durationMs }`: one `POST /api/generate` with Purpose `warmup`, body `model`, `options` (the execution's options, which carry `num_ctx` = `contextWindow`) and `stream` false; no prompt, no `keep_alive`, the profile's `timeoutSec`, one attempt, no telemetry, no cache. A thrown transport or a non-record becomes a classified failure. `doctor` and `-LoadCheck` are 3B and not touched.
