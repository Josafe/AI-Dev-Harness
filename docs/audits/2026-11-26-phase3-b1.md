**Spec ambiguities decided (please confirm or overrule):**
1. **Error-category enum (D-312).** The spec has two lists: `error.category` (FR-308, CLI names) and the engine's 12 (FR-307 maps engine to CLI). I made `error.category` = the FR-308 list (21) plus the reserved `cancelled`, `abandoned` (23, in FR-308 order) and added `error.engineCategory` = the 12 engine categories, each nullable. A test reads the engine's hints table by regex and compares it with the enum, and checks that all 12 FR-307 mappings land in the category enum. **No disagreement** between spec and engine (the stop condition did not trigger).
2. **Reserved categories** `cancelled`/`abandoned` are in the enum (as the run and stage `cancelled`/`abandoned` are); FR-308 says "reserved".
3. **Required keys.** Required: all top-level keys of FR-305; every key of `harness`, `target`, `process`, `request`, `overrides`, `context`, artifacts; stage: `id, kind, agent, attempt, status, reason, startedAtUtc, durationMs, exitCode, warnings`. The other stage keys (`resolution`, `budget`, `callId`, `engineAttempts`, `callDurationMs`, `contextSha256`, `verdict`, `output`, `error`) are typed but optional so pending or skipped stages need not carry them. `error` requires only `category` and `message`.
4. **Timestamps** have a pattern `yyyy-MM-ddTHH:mm:ss[.f]Z` (the spec has none); `Get-HarnessUtcTimestamp` writes `.fff`. `stages[].id` pattern `[a-z][a-z0-9-]*`; `runId` pattern allows 69 characters (suffixed env ids).
5. **Subset rules** (documented in the schema `$comment`): a null whose type allows null skips enum/pattern/minimum; key lookup is ordinal (`Status` is not `status`); a missing required key is reported at the path of the missing key; unparsable or non-object input is `$: wrong_type`; `schemaVersion` failing its enum is `unsupported_schema_version`.
6. **Invariant codes** (spec says only `invariant_*`): `invariant_terminal_exit_code`, `invariant_terminal_ended_at`, `invariant_succeeded_exit_code`, `invariant_succeeded_failed_stage`, `invariant_error_required`, `invariant_duplicate_stage`, `invariant_artifact_path`. Terminal = any status except `queued`/`running`. Invariants run only when the structure is valid. I added no rule that `running` has a null `exitCode`.
7. **`.gitignore`** has `/runs/` (anchored) not `runs/`, so a future `tests/fixtures/runs/` is not hidden; `git check-ignore runs/x/manifest.json` matches.
8. **Claim of a directory without `.claim`** (a hand-made or crashed one): the claim succeeds, per the spec text (CreateNew on `.claim` is the arbiter).
9. **Writer guard.** `Write-HarnessManifest` copies the manifest through `ConvertTo-HarnessPlainData` (every string cast to `[string]`), so a `Get-Content` string no longer hangs `ConvertTo-Json`. The suite proves the hazard (a bare `ConvertTo-Json` of a 200 KB `Get-Content` string does not finish in 3 s) and that the writer survives it. Builders should still use `Read-HarnessTextFile`.
10. Two small helpers not named by the spec, needed by FR-305 string rules: `Get-HarnessFileSha256`, `Get-HarnessTextSha256`, `Get-HarnessUtcTimestamp`, `Read-HarnessTextFile`.

**Deviations:** none from Affected Files. Not verified: behaviour under a second user's processes (`liveness_unverified` is tested with an injected `Get-HarnessProcessInfo`); AC-329 telemetry half; AC-308 checkpoints (B4).

## Details

### Interfaces for B3/B4/B5 (`scripts/lib/manifest.ps1`, dot-source it)

| Function | Contract |
|---|---|
| `Test-HarnessRunId -Id` | bool; grammar of a GIVEN id (1-64 chars, dot never last, stem not a device name) |
| `New-HarnessRunId` | `<UTC yyyyMMddTHHmmssZ>-<8 hex>` (not claimed) |
| `Request-HarnessRunClaim -HarnessRoot -RunId` | one attempt; `CreateDirectory` then `.claim` `CreateNew`; `$true` won, `$false` lost; harness root must be absolute |
| `New-HarnessRunClaim -HarnessRoot [-RunId] [-EnvRunId]` | the FR-304 policy. Returns `{RunId, RunPath, ManifestPath, Source (parameter/environment/generated), Warnings[]}` (`invalid_run_id_env`, `run_id_env_reused`). Throws `invalid_arguments: ...` for an invalid or taken `-RunId`. `-RunId` is untyped: `$null` means not given, `''` is invalid. `-EnvRunId` defaults to `$env:AI_HARNESS_RUN_ID`. It does not set the env var (B4 sets it and restores it in a `finally`) |
| `Get-HarnessRunPath`, `Get-HarnessManifestPath` | `<root>\runs\<id>[\manifest.json]` |
| `Write-HarnessManifest -Path -Manifest [-Retries 50 -DelayMs 20]` | atomic; takes ordered dictionaries, hashtables or objects; throws `internal_error:` after the retries, leaves no temp |
| `Read-HarnessManifestText`, `Read-HarnessManifest -Path [-Retries 25 -DelayMs 20]` | shared-read open, retry on IOException (missing file included) and access denied; BOM dropped; failures are `manifest_invalid: ...` (a JSON parse failure is not retried) |
| `Test-HarnessManifest -Manifest <object or JSON text> [-SchemaPath]` | `{valid, errors[]}`, errors `<path>: <code>` |
| `Get-HarnessRunStatus -Manifest` | `{recordedStatus, status, livenessUnverified}`; B5 maps `livenessUnverified` to the `liveness_unverified` output |
| `Read-HarnessTextFile`, `Get-HarnessFileSha256`, `Get-HarnessTextSha256`, `Get-HarnessUtcTimestamp [-At]` | .NET string and hash sources |

Pitfalls found: `[short]` is not a PowerShell 5.1 type (`[int16]`); `-is [pscustomobject]` is true for any PSObject-wrapped value such as a parsed array (the library tests `GetType().FullName`); a function returning `@(single)` unrolls it (the suite wraps in `@()`); `[string]` parameters turn `$null` into `''` (so `-RunId` is untyped).
