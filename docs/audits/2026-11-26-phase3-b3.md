## 2. Interface for B4 and later

**Entry.** `harness.ps1`: `ConvertFrom-HarnessCliArguments -Arguments @($args)` gives `{ ok, command, options, message }` (token-level errors: unknown command/option, option of another command, duplicate, no value, leftover positional, incomplete name); then `Invoke-HarnessCli -Command -Options [-StageScripts] [-Hook] [-Result]`. Tests call `Invoke-HarnessCli` in process (dot-source `lib\cli.ps1`; it loads config, agent-exec and manifest) and capture the success stream; the exit code is `$Result.exitCode`.

**Validation** (`Test-HarnessCliInvocation`, always run by `Invoke-HarnessCli`): names canonical and allowed for the command, switches `$true`, empty value invalid, required and one-of options, `-Model` with `-Profile`, `-Mode` exactly one of three (default `requirements`), `-Revision` digits (`[int]`, default 0; `revise` needs at least 1), `-Last` positive integer, `-Name` per FR-319, `-RunId` per FR-304 (`status` accepts up to 69 characters), `-TargetPath` (`Resolve-HarnessCliTarget`), `-TaskFile`/`-SpecFile` existing files, the input files of `review`/`revise` (`Get-HarnessCliSpecInputs`). Every failure is `ERROR: invalid_arguments: <text>`, exit 2, before any claim. The text never contains `-Task`.

**Dispatch.** `$script:HarnessCliHandlers` maps the command to a function name, called as `& <function> -Command <canonical> -Options <normalized ordered dictionary> -Context <hashtable>`. Context: `HarnessRoot`, `StageScripts` (absolute paths for `runner`, `validator`, `reviewer`, `reviser`, `scan`, `context`; `-StageScripts` replaces any of them with a mock), `Hook` (script block or `$null`), `ExitCode` (the handler sets it; default 2). Handlers write to the success stream and never call `exit`. Options carry `TargetPath`, `TaskFile`, `SpecFile` as absolute normalized paths and `Task` as given.

**Plugging in `specify` (B4).** Define `Invoke-HarnessCommandSpecify` (replace the stub), dot-source `workflow.ps1` (and `telemetry.ps1`) in the loader of `cli.ps1`, claim with `New-HarnessRunClaim -HarnessRoot $Context.HarnessRoot -RunId <Options.RunId or $null>`, print `RUN_ID:`, build the manifest with `New-HarnessCliManifest -RunId -Workflow -HarnessRoot [-TargetPath] [-Warnings]` (fills `harness` incl. git state and registry hash, `process`, empty `request`; fill `request`, `stages`, ...), validate with `Test-HarnessManifest`, write with `Write-HarnessManifest`, print `ERROR:` then `MANIFEST:` last. `Get-HarnessLoadCheckError -LoadResult` gives `{ category, message, hint, httpStatus = $null }` for the `load-check` stage error (gate finding 13). `Invoke-HarnessCommandUnsupported` is a complete worked example of claim, manifest, protocol and exit.

**Fake host.** `Invoke-Case -Script harness.ps1 -ArgumentList @(...) [-VersionSteps ...]` runs `harness.ps1` with `$args` in the engine fake host; `New-Step "ok" @{ version = "..." }` answers `/api/version`. The suite copies `harness.ps1`, `validate-spec.ps1` and `run-manifest.schema.json` into its temporary harness and empties `PATH`, so git, `nvidia-smi` and `ollama` are absent unless a case puts a fake `.cmd` there.

## 3. Decisions where the spec is silent or open

1. **Exit-code carrier:** extra `-Result` parameter (summary 3).
2. **Doctor shape.** `-Json`: `{ registry {path, schemaVersion, warnings}, ollama {url, reachable, version, ps}, models[ {model, installed, loadChecks[ {agents, numCtx, loaded, category, hint, durationMs} ]} ], vramFreeMiB, findings[ {code, severity (error|info), model, message, hint} ], exitCode }`. `ps` is the lines of `ollama ps` or null (absent, failing or slow tool; also an empty answer). Exit 2 (invalid registry, any `/api/tags` failure) prints only the `ERROR:` line, with or without `-Json`; exit 1 and 0 print the report.
3. **`ollama_unreachable`** is every failure of `/api/tags` (refused, timeout, 5xx, 4xx): the FR-309 tokens have no other name.
4. **`-LoadCheck` skips a model that is not installed** (it already has its `model_not_installed` finding); distinct pairs are keyed by lower-case model plus the effective options.
5. **Load-check error wording (gate finding 13, owner decision).** `error.httpStatus` null; `error.message` = `The model load check failed with the category '<category>'. <hint>`. `Test-OllamaModelLoad` and its A4 tests are unchanged. One applied sentence is in FR-318.
6. **`stages -Json`:** `{ "stages": [ { name, supported, agent, reason } ] }` for the 11 commands in table order; agents `spec`, `spec-reviewer`, `spec-reviser`, and `developer` for `develop`; reasons `no_local_agent` (architecture, plan, qa, code-review), `planned_phase_5` (develop).
7. **`config`:** one record per file of `.ai\agents\` in ordinal order (`agents[]` with the FR-309 fields, `warnings[]` of the registry at top level); `-Agent` must name a file; `options` is not printed. A missing or invalid registry or an unknown `-Profile` is `registry_invalid`.
8. **`validate`:** the validator's stdout passes through; exit 0, 1, 3 pass through; a throw or any other code is exit 2 with `ERROR: stage_failed:` (fixed wording); a missing spec file is `invalid_arguments`.
9. **Unsupported stages** write the manifest once, at the end (status `failed`, exit 4); `target.artifactDir` is the path `<target>\.ai-harness\specs` although nothing is created; `-TargetPath` gets the FR-302 checks only (the reparse checks of `.ai-harness` and `specs` are B4's FR-319); `harness.registry*` and `ollamaUrl` are best effort (null when the registry cannot be read).
10. **Value details FR-302 leaves open:** the colon form `-Name:value` is an unknown option; an empty or blank value is an error; `-Revision` and `-Last` accept 1 to 9 digits; command and option names match case-insensitively; a command token that starts with `-` is "no command given".
11. **AC-107** forbids model-name literals under `scripts\`, tests included: the two names of `config-v2-current.json` are read from the fixture, every other expected value of the AC-314 table is a literal.
12. **Case time:** the suite takes about 80 s (about 100 child processes); `test-all` still has no suite near its timeout.
